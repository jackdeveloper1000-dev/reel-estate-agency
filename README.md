# RealAssets AI — Cinematic Real Estate Films (Node + React + MySQL)

Paste a property listing link → the app collects the listing photos and automatically renders a
cinematic Full-HD film: eased camera moves (push-ins, pans, tilts), cross-transitions, golden colour
grade, cinema letterbox, title overlay (address + price), a branded agent end card and a music bed.

**Stack:** MySQL (XAMPP) · Express · React (Vite) · Node — video rendering with FFmpeg (bundled via `ffmpeg-static`).
**Theme:** black & gold.

---

## 1. Requirements (Windows)

| Need | Notes |
|---|---|
| Node.js 18.17+ (20 LTS recommended) | https://nodejs.org |
| MySQL | Use the MySQL that comes with XAMPP – start it in the **XAMPP Control Panel**. The `realassets_ai` database and its tables are created automatically on first start. Login details go in `server/.env` (`MYSQL_USER`, `MYSQL_PASSWORD`; XAMPP default is `root` with no password). |
| FFmpeg | Nothing to install — `ffmpeg-static` downloads it during `npm install`. To use your own, set `FFMPEG_PATH` in `server/.env`. |

## 2. Install & run

**Easiest (Windows):** double-click **`start.bat`** in the project folder. It installs everything and starts the app.
It also starts XAMPP's MySQL if it isn't running yet.

Manual:

```bash
cd C:\xampp\htdocs\realassets_ai
npm run setup        # installs root, server and client packages
npm run dev          # API on :5000, website on http://localhost:5173
```

Open **http://localhost:5173**, paste a listing URL, press **Create Film**.

### Production (single server)
```bash
npm run build        # builds client/dist
npm start            # Express serves the site + API on http://localhost:5000
```

## 3. How it works

```
URL ──► scraper (server/src/services/scraper.js)
        • og:image, JSON-LD, <img>/srcset/lazy attrs, gallery links, Next.js/inline JSON
        • filters logos/icons/agent photos, de-duplicates sizes, keeps photos ≥ 640×400
        • reads address & price from JSON-LD / page text
   ──► MySQL: `projects` row (details, settings, status/progress, video) + `project_images` rows (photo order & selection)
   ──► render queue (server/src/services/jobs.js, one film at a time)
   ──► FFmpeg engine (server/src/services/videoEngine.js)
        1. each photo → shot with eased Ken-Burns move from a 2× supersampled frame + colour grade
        2. end card: blurred last photo + agent name / phone / agency
        3. xfade transitions, title overlay, letterbox, fades, music → MP4 (H.264/AAC, faststart)
```

**Studio page** (after import): tick/untick and drag-reorder photos, edit address/price/agent
details, pick format (16:9 / 9:16 / 1:1), transitions, colour grade, camera motion, seconds per shot,
letterbox, and music (built-in ambient score, your own track, or none) → **Regenerate film**.

### API
| Method | Path | Purpose |
|---|---|---|
| POST | `/api/projects` `{url, settings?, autoRender?}` | Import a listing (async) |
| POST | `/api/projects/upload` (multipart `photos[]`) | Create from uploaded photos |
| GET | `/api/projects` / `/api/projects/:id` | List / poll status |
| PATCH | `/api/projects/:id` `{details, settings, images:[{id,selected}]}` | Save edits & photo order |
| POST | `/api/projects/:id/photos` · `/music` | Add photos · upload music |
| POST | `/api/projects/:id/render` | Queue a render |
| POST | `/api/projects/:id/retry` · DELETE `/api/projects/:id` | Retry import · delete |

Files are stored in `server/storage/projects/<id>/` and served from `/media/...`.

## 4. Notes & limits
* Some big portals (realestate.com.au, domain.com.au, Zillow) block automated requests. When that
  happens the app shows a clear message and you can **upload the photos** instead. A headless-browser
  importer (Puppeteer) can be added later for those sites.
* Render time depends on CPU: roughly 10–15 s per shot at 1080p on a modern laptop.
* Only use music you own or have a licence for. The built-in ambient score is generated by FFmpeg, so
  it is royalty-free.

## 5. Database (MySQL)
Tables (created automatically – see `server/database/schema.sql`, which you can also import in phpMyAdmin):

* **projects** – one row per film: source URL, status/progress, `details`, `settings` and `video` stored as JSON text.
* **project_images** – the photos of each project, with `position` (order) and `selected`; deleted automatically with the project.

Browse the data at http://localhost/phpmyadmin → `realassets_ai`.

## 6. Accounts, OTP login & payments

* **Sign up / log in** with name + mobile number and a 6-digit SMS code (no passwords). Sessions last 30 days (httpOnly cookie).
* **Pay per film (Razorpay):** importing photos is free; the film page is a 4-step wizard
  (Photos → Details → Style → Music & Pay) and the payment is taken on the last step. One payment = one render
  (a failed render can be retried for free). Unused credits stay on the account.
* **Finished films are final:** after a successful render the listing photos and uploaded music are deleted;
  only the MP4 (and its poster) is kept, and the film page shows just the video and *Download MP4*.
* **Private films:** each user only sees, plays and downloads their own films (`/media` is protected too).
* **Phones:** app-style bottom bar (Create · My Films · Account); the film studio uses Photos / Details / Style / Music tabs
  with a fixed *Make Film* bar.

Settings in `server/.env` (see `.env.example`):

| Setting | What it does |
|---|---|
| `APP_SECRET` | Long random string that signs logins – set it before going live |
| `SMS_PROVIDER` | `console` (test – code shown on screen), `fast2sms`, `msg91` or `twilio` + their keys |
| `RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET` | Razorpay API keys (test keys start with `rzp_test_`). Empty = demo payments |
| `PRICE_PER_FILM_INR` | Price of one film (default 499) |
| `SMS_NOTIFY_FILM_READY` | `true` = text the user when their film is ready |

New tables: `users`, `otp_codes`, `payments`; `projects.user_id` links each film to its owner.
Films made before accounts existed have no owner and are hidden.

## 7. API key

Every `/api` request must carry the header `x-api-key: <key>` once `API_KEY` is set in `server/.env`
(comma-separate several keys, e.g. one for the website and one for the app). `/api/health` stays open and
reports `apiKey: valid / missing or invalid`. Set the matching key in:

* `client/.env` → `VITE_API_KEY=…` (restart `npm run dev` / `start.bat` after changing it)
* `mobile/.env` → `API_KEY=…`

With `API_KEY` empty the check is off. Note: a key inside a website or app can be extracted by a determined
user – it stops casual/bot access to the API; logins (OTP) and payments still protect each user's films.
